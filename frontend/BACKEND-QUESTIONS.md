# Связка фронтенда с бэкендом

Контракт API: `docs/openapi.json`, правила и коды ошибок: `docs/BACKEND-DEV.md`, `docs/API-ANSWERS.md`.
Фронт работает на заглушках (`VITE_USE_MOCKS=true`, `src/api/mocks/`). Чтобы работать с настоящим сервером:

```
VITE_USE_MOCKS=false
VITE_API_URL=http://localhost:5000/api/v1   # адрес из launchSettings бэкенда
```

## Уже сверено с openapi.json (вход, регистрация, 2FA, профиль, анкета, подбор)
- Вход, регистрация (`acceptChatModeration`), `confirm-email`, `reset-password` (`userId` + `token`), капча (`captchaToken`).
- 2FA: вход в два шага, обязательная настройка для служебных аккаунтов (`twoFactorToken`), включение и отключение в настройках, резервные коды, сеансы.
- Токен: после входа берём полный профиль через `GET /me` (в ответе входа нет `skillsComplete`).
- Роли: `User`, `Moderator`, `Admin`, `SuperAdmin`. Коды ошибок: нижний регистр, перевод ищется без учёта регистра.
- Каталог навыков, языки занятий, `GET/PUT /me/skills`, `PUT /me` (языки и часовой пояс), `POST /skills/suggestions`.
- Профиль `GET /me`, `GET /users/{id}`, подбор `GET /matches`.

## Ещё на заглушках (бэкенда пока нет, этап 4+)
Заявки, обмены, уроки, чат, отзывы, уведомления, главная (`GET /me/dashboard`), видеозвонок, модерация, админка, экспорт и удаление данных, загрузка аватара.

## Допущения и что проверить при первом запуске с сервером
- `GET /matches`: серверного поиска по имени нет, поле поиска в шапке фильтрует уже полученную страницу (до 50).
- Онбординг: `isSearchable` отправляем как в профиле, показ в подборе сервер включает сам после полной анкеты.
- Блокировки пользователей (`/users/{id}/block`, `/me/blocks`) во фронте ещё не сделаны.
- QR-код для 2FA пока не рисуем: показываем ключ и ссылку `otpauth://`. QR нужна небольшая библиотека, спросим перед добавлением.
- SignalR (`/hubs/chat`, `/hubs/notifications`): пока опрос.
