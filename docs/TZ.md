# ТЗ v2.2: SkillSwap — платформа взаимного обмена знаниями

Nov 17, 2026 · @Muhammad

Версия 2.2 закрывает противоречия v2.1 и готова к старту разработки. Изменения относительно v2.1 перечислены в конце, в разделе 16.4.

## 1. Общие сведения

SkillSwap — адаптивная веб-платформа, где два человека бесплатно обучают друг друга своим навыкам. Уже в MVP есть встроенный чат, голосовые сообщения и видеозвонки на собственном медиасервере без установки сторонних программ.

| Параметр | Значение |
| --- | --- |
| Рабочее название | SkillSwap (будет заменено до релиза, см. раздел 16.3) |
| Тип продукта | Адаптивное веб-приложение (SPA); нативное мобильное приложение — после запуска |
| Регион | Международный запуск, не только Таджикистан |
| Бизнес-модель | Бесплатный взаимный обмен; переводы денег между пользователями запрещены. Платные функции возможны после MVP |
| Языки интерфейса | Таджикский (tg), русский (ru), английский (en); новые добавляются файлом перевода без изменения кода |
| Возраст пользователей | 16+ с дополнительной защитой 16–17 лет (раздел 10.4) |
| Backend | C#, ASP.NET Core (.NET 8+), Clean Architecture (обычные сервисы, без CQRS и MediatR), ASP.NET Core Identity, EF Core, PostgreSQL, Redis, Hangfire |
| Frontend | React 18+, TypeScript, Vite, React Router, TanStack Query, Tailwind CSS — простая структура папок |
| Видео и голос | Собственный LiveKit (open source) + TURN на порту 443/TLS |

**Основные термины**

- **Обмен (Exchange)** — договорённость двух пользователей обучать друг друга выбранным навыкам 30 или 60 дней.
- **Сессия (Session)** — один урок 45 минут в видеозвонке: один участник преподаёт, второй учится.
- **Матч (Match)** — совпадение интересов: полное (А умеет то, что хочет В, и наоборот) или частичное (совпадение только в одну сторону).
- **Обращение (Case)** — заявка модератору: несправедливый отзыв, нарушение правил или систематические неявки.
- **Служебный аккаунт** — отдельная учётная запись модератора, админа или суперадмина; в обменах не участвует.

## 2. Цели и метрики

Главная цель — чтобы пары доходили до конца обмена и оба участника реально получали знания, а не останавливались на регистрации.

- Автоматически подбирать партнёров по взаимным навыкам, языку и часовому поясу.
- Дать все инструменты внутри платформы: чат, голосовые, видеозвонки, демонстрацию экрана.
- Автоматически фиксировать факт урока по данным медиасервера.
- Честные слепые отзывы и прозрачное разрешение споров.
- Строгая изоляция данных и разграничение прав.

| Метрика (первые 6 месяцев) | Цель | Источник |
| --- | --- | --- |
| Обмены, завершённые успешно | ≥ 40% | Статусы Exchange |
| Запланированные сессии, которые состоялись | ≥ 70% | События LiveKit |
| Средняя оценка завершённых обменов | > 4,0 из 5 | Опубликованные отзывы |
| Обмены с обращением к модератору | ≤ 5% | Cases |
| Первичное рассмотрение обращения | ≤ 24 ч (высокий) / ≤ 72 ч | Метки времени Case |
| Звонки без критического обрыва | ≥ 95% | Логи WebRTC |

## 3. Роли и права доступа

В системе 4 роли и 4 рабочие зоны. Пользователь учится и преподаёт; три служебные роли управляют платформой и в обменах не участвуют.

- **Пользователь** — профиль и навыки, поиск пар, обмены, чат и звонки, отзывы, обращения и апелляции.
- **Модератор** — разбирает обращения. Читает чат пары только после взятия обращения в работу и только до его закрытия.
- **Админ** — пользователи (блокировка), модераторы, каталог навыков, апелляции, запросы на бан, статистика. Доступа к личным чатам нет.
- **Суперадмин** — все права админа + назначение и снятие админов, полный журнал аудита, системные настройки.

**Правила служебных аккаунтов**

1. Служебный аккаунт отделён от личного: нет анкеты, подбора, чатов обмена и рейтинга.
2. Модератор и админ назначаются через email-приглашение (`StaffInvitation`, срок 72 ч). По ссылке создаётся отдельная учётная запись с обязательной 2FA TOTP.
3. Личный аккаунт сотрудника привязывается через `LinkedUserId` (не более одного служебного на личный). Модератор не может брать обращения, где участвует его личный аккаунт или его бывшие партнёры.
4. Модераторов приглашает и снимает админ или суперадмин. Админов — только суперадмин.
5. Первый суперадмин создаётся при развёртывании из переменных окружения, а не через публичную регистрацию.
6. Нельзя снять или заблокировать последнего активного суперадмина. Никто не может менять права самому себе.
7. Любое изменение ролей или настроек требует повторного ввода пароля и кода 2FA и пишется в журнал аудита.

| Очередь обращений, взятие в работу | Нет | Да | Просмотр статусов | Просмотр статусов |

## 4. Основной сценарий

Путь пользователя — от регистрации до публикации отзывов. Модератор подключается только по обращению одного из участников.

1. **Регистрация:** учётная запись, дата рождения, подтверждение email, согласие с правилами и с чтением чата модератором при споре.
2. **Анкета:** «Умею», «Хочу изучать», языки общения, часовой пояс.
3. **Подбор и заявка:** полные и частичные матчи, заявка с навыками и сроком 30 или 60 дней.
4. **Согласование:** партнёр отвечает в течение 7 дней; при принятии открываются карточка обмена и чат.
5. **Уроки:** пара сама договаривается о времени в чате; уроки по 45 минут в видеозвонке, посещаемость фиксируется автоматически.
6. **Завершение и отзывы:** слепые отзывы; при споре — обращение, модератор изучает переписку и выносит решение.

## 5. Регистрация, каталог навыков и подбор

После подтверждения email пользователь попадает на обязательную анкету. Подбор открывается после минимум 1 навыка в «Умею» и 1 в «Хочу изучать».

### 5.1 Регистрация и вход

Аутентификация построена на ASP.NET Core Identity: подтверждение email, блокировка после неудачных попыток, сброс пароля и TOTP берутся из Identity, а не пишутся вручную.

| ID | Требование | Этап |
| --- | --- | --- |
| FR-1 | Регистрация по email и паролю (минимум 8 символов, буквы и цифры), подтверждение email одноразовой ссылкой | MVP |
| FR-2 | Выбор языка (tg, ru, en); по умолчанию по заголовку `Accept-Language` | MVP |
| FR-3 | Дата рождения (младше 16 лет — отказ), принятие соглашения и согласие на доступ модератора к переписке при обращении | MVP |
| FR-4 | Сброс пароля через одноразовый токен на email (срок 1 час) | MVP |
| FR-5 | Капча (Cloudflare Turnstile) на регистрации и входе; блокировка входа на 15 минут после 5 неудачных попыток | MVP |
| FR-6 | Вход с 2FA в два шага: `/auth/login` возвращает `requires2fa`, затем `/auth/login/2fa` с кодом; резервные коды восстановления | MVP |
| FR-7 | Вход через Google | Post-MVP |

### 5.2 Анкета и каталог навыков

- «Умею»: навыки из каталога, уровень (Начальный, Средний, Продвинутый) и краткое описание опыта.
- «Хочу изучать»: целевые навыки и текущий уровень.
- Языки занятий и часовой пояс (IANA, например `Asia/Dushanbe`).
- Каталог «Категория → Навык»: названия на трёх языках и синонимы для поиска. Один навык можно добавить в каждое направление только один раз.
- Пользователь предлагает новый навык; админ одобряет, объединяет с существующим или отклоняет.
- На старте 3 категории (IT, Иностранные языки, Дизайн); список навыков внутри них админ заполняет в панели, без изменения кода.

### 5.3 Подбор и антиспам

- Первыми показываются полные матчи, затем частичные (инициатор предлагает свой навык в тексте заявки).
- Сортировка: общий язык → меньшая разница часовых поясов → подходящий уровень → рейтинг → активность за 7 дней.
- Фильтры: навык, язык, уровень, минимальный рейтинг. Скрытые, заблокированные и заблокировавшие друг друга пользователи исключаются.
- Пользователи 16–17 лет и 18+ подбираются по правилам раздела 10.4.
- Заявка: навык преподавания, навык изучения, срок 30 или 60 дней, сообщение. Действует 7 дней; чат открывается после принятия.

**Антиспам-лимиты** (значения хранятся в `SystemSettings`):

- не более 3 активных обменов одновременно;
- не более 5 ожидающих исходящих заявок;
- не более 10 новых заявок в сутки;
- повторная заявка тому же пользователю после отказа — не раньше чем через 30 дней.

При принятии заявки лимит активных обменов перепроверяется у обоих участников внутри транзакции с блокировкой (раздел 10.2).

## 6. Обмен и сессии

Участники сами согласуют расписание в чате. Платформа фиксирует договорённости, показывает время в часовом поясе каждого, напоминает и сама подтверждает факт урока.

### 6.1 Жизненный цикл обмена

- **Срок и продление:** 30 или 60 дней; по согласию обоих — одно продление на 30 дней.
- **Баланс:** счётчик проведённых уроков в роли преподавателя у каждого (например, 3 : 2). При разнице больше 3 обоим показывается мягкое напоминание.
- **Завершение:** автоматически по истечении срока или досрочно, когда оба нажали «Завершить».
- **Досрочный выход:** любой участник может прервать обмен с указанием причины → «Прерван». Запланированные сессии отменяются.
- **Заморозка:** пока обмен заморожен модератором, срок не идёт. При разморозке `EndDate` сдвигается на время заморозки. Запланированные сессии отменяются без виновного.

### 6.2 Планирование сессий

- **Слот:** участник отправляет в чат карточку: дата, время, кто преподаёт, тема (необязательно). Длительность — 45 минут. Слот нельзя предложить меньше чем за 1 час до начала и позже `EndDate` обмена.
- **Ответ на слот:** партнёр принимает или отклоняет. Если ответа нет до начала, слот истекает (`Expired`).
- **Конфликты:** сервер не даёт подтвердить слот, если у любого из участников в это время уже есть урок, в том числе в другом обмене. Проверка идёт в транзакции с блокировкой обоих пользователей (раздел 10.2).
- **Перенос:** перенос запланированного урока создаёт новое предложение с новым временем (статус снова `Proposed`); старое время освобождается. Если партнёр не принял новое время, урок истекает.
- **Напоминания и отмены:** за 24 часа и за 15 минут (в интерфейсе и на email). Отмена или перенос без последствий — не позднее чем за 2 часа; позже — `LateCancelled`, учитывается модератором.

### 6.3 Автоматическая фиксация урока

Итог урока определяется дважды: предварительно на 15-й минуте и окончательно в момент закрытия комнаты (плановый старт + 75 минут). Обе проверки делает фоновая задача Hangfire, которая ставится при подтверждении слота.

| Что показали события LiveKit | Итоговый статус |
| --- | --- |
| К закрытию комнаты оба были в комнате одновременно ≥ 30 минут суммарно | `Completed` — засчитывается в баланс |
| На 15-й минуте один в комнате, второго нет | Предварительно `NoShow` с указанием виновника |
| Партнёр опоздал, но к закрытию совместное время ≥ 30 минут | `NoShow` меняется на `Completed`; опоздание сохраняется (`LateJoinMinutes`) |
| Никто не зашёл за 15 минут | Предварительно `Missed`; если потом оба провели ≥ 30 минут — `Completed` |
| Оба были, но совместно < 30 минут (обрыв связи) | `Unconfirmed` — оба могут подтвердить урок вручную в течение 24 часов, иначе он не засчитывается |

После 3 окончательных `NoShow` партнёра пострадавший может прервать обмен без последствий для себя.

## 7. Чат, голосовые и видеозвонки

Вся коммуникация пары идёт внутри платформы, без обмена личными мессенджерами и номерами.

### 7.1 Чат обмена

- **Транспорт:** SignalR, хаб `/hubs/chat`, одна группа на обмен, автопереподключение. Уведомления идут через отдельный хаб `/hubs/notifications`.
- **Контент:** текст, голосовые до 2 минут (WebM/Opus), файлы до 20 МБ (pdf, docx, xlsx, pptx, zip, txt, png, jpg, webp).
- **Интерактив:** статусы доставки и прочтения, «печатает…», карточки слотов с кнопками «Принять» и «Другое время».
- **История для модерации:** правка и удаление — в течение 15 минут; исходный текст сохраняется в `MessageRevisions` и виден модератору по обращению.
- **Антифрод:** на номера карт и призывы к оплате выводится предупреждение о запрете денежных расчётов. Проверка идёт до шифрования сообщения.
- **Сроки:** чат активен весь обмен; ещё 30 дней после завершения — только чтение; через 90 дней — удаление (раздел 10.3). В замороженном обмене чат только для чтения.

### 7.2 Видеозвонки и LiveKit

- **Комната:** звонок один на один в браузере, камера и микрофон, демонстрация экрана, мини-чат, проверка устройств перед входом. Имя комнаты = `session-{SessionId}`.
- **Время:** вход открывается за 10 минут до старта и закрывается через 30 минут после планового окончания (окно 85 минут). На 40-й минуте — мягкое уведомление «осталось 5 минут». При закрытии окна бэкенд удаляет комнату через LiveKit API.
- **Сеть:** автопереподключение; при плохом канале приоритет у звука (от 0,3 Мбит/с), видео понижается.
- **Приватность:** потоки шифруются WebRTC (DTLS-SRTP) и не записываются. Хранятся только время входа и выхода.

| Компонент | Решение |
| --- | --- |
| Медиасервер | LiveKit Server в Docker на отдельном VPS, ближе к основной аудитории |
| TURN | Встроенный TURN LiveKit или coturn на 443/TLS |
| Доступ в комнату | Бэкенд выдаёт короткий токен LiveKit только двум участникам и только в окне сессии; в замороженном обмене токен не выдаётся |
| Посещаемость | Подписанный webhook (`participant_joined`, `participant_left`, `room_finished`); каждое событие записывается один раз по уникальному id (раздел 11.1) |
| Сервер на старте | Ориентир 4 vCPU, 8 ГБ RAM, канал от 500 Мбит/с; масштабирование добавлением узлов |

## 8. Отзывы и обращения

Отзывы слепые и взаимные; споры решаются через формальный процесс модерации.

### 8.1 Правила отзывов

**Когда можно оставить отзыв:**

1. Обмен завершён штатно и состоялась хотя бы 1 совместная сессия. Если каждый провёл ≥ 3 уроков преподавателем, отзыв получает отметку «Полный обмен».
2. Обмен прерван досрочно и состоялась хотя бы 1 сессия.
3. У партнёра ≥ 3 неявок — пострадавший оставляет отзыв в одностороннем порядке.
4. Если не состоялось ни одной сессии и нет неявок — отзывы недоступны.

- **Формат:** 1–5 баллов по четырём критериям (знание предмета, умение объяснять, пунктуальность, вежливость) и текст 20–1000 символов. Срок — 14 дней после закрытия обмена.
- **Слепая публикация:** отзывы становятся видны одновременно, когда написаны оба или через 7 дней после первого. После публикации править нельзя.
- **Рейтинг:** среднее из средних оценок по четырём критериям всех опубликованных и нескрытых отзывов; хранится в `Users.RatingAvg` и `RatingCount` и пересчитывается при публикации или скрытии отзыва. Профиль с менее чем 3 отзывами показывается как «Новичок».
- **Удалённый аккаунт:** его отзывы остаются с подписью «Удалённый пользователь» и продолжают влиять на рейтинг адресатов.

### 8.2 Обращения

| Тип | Основание и срок подачи | Приоритет |
| --- | --- | --- |
| Спор по отзыву | Несправедливая, оскорбительная или ложная оценка; 14 дней после публикации | Обычный (≤ 72 ч) |
| Жалоба на поведение | Оскорбления, угрозы, домогательства, спам, вымогательство; пока есть чат (до 90 дней после обмена) | Высокий (≤ 24 ч) |
| Неявки и срыв обмена | Систематическое уклонение, недобросовестные уроки; 30 дней после обмена | Обычный (≤ 72 ч) |

Любая жалоба с участием пользователя 16–17 лет получает высокий приоритет.

1. **Подача:** категория, описание и ссылки на конкретные сообщения чата (таблица `CaseEvidence`). При споре по отзыву его влияние на рейтинг временно замораживается. До взятия в работу заявитель может отозвать обращение.
2. **Взятие в работу:** проверка конфликта интересов, создаётся `ChatAccessGrant`, обоим участникам один раз приходит уведомление: «Модератор приступил к рассмотрению и получил временный доступ к переписке». Каждый запрос истории пишется в `AuditLogs`, но новых уведомлений не создаёт.
3. **Пояснения:** модератор задаёт вопросы сторонам в интерфейсе обращения; на ответ 48 часов. По истечении кейс автоматически возвращается в работу, решение принимается по имеющимся фактам.
4. **Решение:** с обязательным обоснованием; `ChatAccessGrant` отзывается сразу.
5. **Апелляция:** один раз, в течение 7 дней, к админу. Админ видит материалы кейса и приложенные сообщения, но не весь чат. Если нужна повторная проверка чата, админ назначает другого модератора: тот получает новый `ChatAccessGrant` и пишет заключение, а окончательное решение принимает админ.

### 8.3 Решения модератора

- **Оставить отзыв** — критика конструктивна и не нарушает правил.
- **Скрыть отзыв** — оскорбления, клевета или очевидная месть.
- **Предупреждение** — в профиль нарушителя; 3 активных предупреждения за 12 месяцев автоматически создают `BanRequest` для админа.
- **Принудительно завершить обмен** — можно из активного или замороженного состояния.
- **Заморозить обмен и запросить бан** — при угрозах или мошенничестве: чат становится только для чтения, звонки блокируются, админ получает `BanRequest` с обоснованием.

## 9. Статусные модели

Все переходы статусов заключены в методы доменных сущностей. Недопустимый переход бросает `InvalidStateTransitionException` → HTTP 409 Conflict. Переходов, которых нет в таблицах, не существует.

### 9.1 Заявка (ExchangeRequest)

| Из | В | Кто и при каком условии |
| --- | --- | --- |
| \[начало\] | Pending | Отправитель создал заявку; проверены лимиты и блокировки |
| Pending | Accepted | Получатель принял; в той же транзакции перепроверен лимит обменов у обоих и создан Exchange |
| Pending | Declined | Получатель отклонил; кулдаун 30 дней |
| Pending | Withdrawn | Отправитель отозвал |
| Pending | Expired | Фоновая задача через 7 дней или если один из пользователей заблокирован или удалён |

### 9.2 Обмен (Exchange)

| Из | В | Кто и при каком условии |
| --- | --- | --- |
| \[начало\] | Active | Заявка принята |
| Active | Completed | Истёк `EndDate` (фоновая задача) или оба нажали «Завершить» |
| Active | Aborted | Участник вышел досрочно с причиной; либо модератор принудительно завершил; либо участник заблокирован или удалил аккаунт |
| Active | Frozen | Модератор заморозил по жалобе высокого приоритета; записывается `FrozenAt` |
| Frozen | Active | Модератор разморозил; `EndDate` сдвигается на длительность заморозки |
| Frozen | Aborted | Модератор закрыл обмен по итогам проверки |

Истечение срока на замороженный обмен не действует. Продление не меняет статус: меняются `EndDate` и `IsExtended`.

### 9.3 Сессия (Session)

| Из | В | Кто и при каком условии |
| --- | --- | --- |
| \[начало\] | Proposed | Участник предложил слот |
| Proposed | Scheduled | Партнёр подтвердил; нет пересечений (проверка с блокировкой) |
| Proposed | Declined | Партнёр отклонил |
| Proposed | Expired | Наступило время начала, а ответа нет |
| Proposed | Cancelled | Автор отозвал предложение |
| Scheduled | Proposed | Перенос: новое время ждёт подтверждения; меньше чем за 2 часа — нельзя, только отмена |
| Scheduled | Cancelled | Отмена за 2 часа и раньше, либо обмен заморожен или завершён |
| Scheduled | LateCancelled | Отмена меньше чем за 2 часа |
| Scheduled | InProgress | Webhook: первый участник вошёл в комнату |
| Scheduled | Missed | Проверка на 15-й минуте: никто не зашёл |

## 10. Безопасность и приватность

Все проверки прав, лимитов и временных окон выполняются на сервере. Скрытие кнопок во фронтенде — только удобство.

### 10.1 Аутентификация

- **Пароли:** ASP.NET Core Identity `PasswordHasher` (PBKDF2, число итераций не ниже 100 000).
- **Токены:** Access JWT 15 минут в заголовке `Authorization: Bearer`, хранится только в памяти браузера. Refresh-токен 30 дней в cookie `HttpOnly; Secure; SameSite=Strict` с ротацией. Повторное использование старого refresh-токена отзывает все сеансы пользователя.
- **SignalR:** токен передаётся через `access_token` в строке подключения; сервер не пишет его в логи.
- **2FA (TOTP):** обязательна для служебных ролей, по желанию для пользователей; 10 резервных кодов.
- **Устройства:** список активных сеансов (браузер, IP, время) и завершение одного или всех.
- **Блокировка аккаунта:** сразу отзывает все refresh-токены и отключает SignalR-подключения.

### 10.2 Угрозы и меры защиты

| Риск | Защита |
| --- | --- |
| Доступ к чужому чату или сессии подбором Guid (IDOR) | Ресурсная авторизация (`IAuthorizationHandler`) в каждом запросе: участие в обмене или активный grant |
| Модератор читает чат без основания | Проверка активного `ChatAccessGrant` (без `RevokedAt`); каждый запрос истории — в `AuditLogs` |
| Подключение к чужой группе SignalR или комнате | Проверка прав при подписке на группу; токен LiveKit только в окне сессии |
| Поддельный webhook | Проверка подписи JWT в заголовке `Authorization` по API Secret и хеша тела запроса |
| **Гонка: два урока в одно время или 4-й обмен** | В транзакции блокируются строки обоих пользователей (`SELECT … FOR UPDATE`, всегда в порядке возрастания Id, чтобы не было взаимных блокировок), затем проверка пересечений и лимитов, затем запись |
| Гонка: два одновременных изменения одной записи (принять и отозвать заявку) | Оптимистичная блокировка по `xmin` (concurrency token EF Core) → 409 при конфликте |
| Вредоносные файлы | Проверка сигнатур (magic bytes), белый список типов, хранение в закрытом бакете MinIO, выдача по подписанной ссылке на 5 минут с `Content-Disposition: attachment` |
| Перебор паролей, спам, XSS, SQL-инъекции | Rate Limiter .NET, параметризованные запросы EF Core, строгий Content-Security-Policy, без `dangerouslySetInnerHTML` |

### 10.3 Хранение и удаление данных

- **Шифрование переписки:** текст сообщений шифруется на сервере (Data Protection API, AES-256). Модератор может читать чат при споре, а украденная копия БД без ключей бесполезна.
- **Ключи шифрования:** хранятся в отдельной таблице (`PersistKeysToDbContext`) и сами защищены сертификатом, который лежит вне БД. Ключи и сертификат входят в резервное копирование; старые ключи не удаляются. Потеря ключей = потеря всех чатов.
- **Срок хранения:** сообщения и вложения удаляются через 90 дней после завершения обмена, если нет открытого обращения или апелляции. Сообщения, приложенные к обращению, хранятся вместе с ним 1 год.
- **Право на забвение:** выгрузка своих данных в JSON (фоновая задача, ссылка на email) и удаление профиля: личные данные затираются, статус `Deleted`, активные обмены прерываются.
- **Журнал аудита:** только добавление записей. У пользователя БД, под которым работает приложение, нет прав `UPDATE` и `DELETE` на `AuditLogs`.

### 10.4 Защита пользователей 16–17 лет

Подростки оказываются один на один в видеозвонке без записи, поэтому для них действуют отдельные правила. Окончательное решение по возрасту — до пилота (раздел 16.3).

- Возраст считается по дате рождения; пользователь сам её изменить не может (только через поддержку).
- По умолчанию 16–17 лет подбираются только с 16–17 лет (переключатель суперадмина в `SystemSettings`).
- В чате и звонке всегда видна кнопка «Пожаловаться»; жалоба из звонка сразу замораживает обмен.
- Жалобы с участием несовершеннолетних всегда имеют высокий приоритет.

## 11. Архитектура

Клиент-серверная система: модульный монолит на ASP.NET Core и SPA на React, контракт между ними — OpenAPI.

### 11.1 Backend (Clean Architecture)

```
src/
├── SkillSwap.Domain/          # сущности, enum, переходы статусов, доменные исключения
├── SkillSwap.Application/     # сервисы по модулям (AuthService, ExchangeService, SessionService…), DTO, валидаторы, интерфейсы
├── SkillSwap.Infrastructure/  # EF Core + Identity, Redis, MinIO, LiveKit SDK, SMTP, Hangfire
└── SkillSwap.Api/             # контроллеры, SignalR-хабы, AuthorizationHandlers, ProblemDetails, Swagger
tests/
├── SkillSwap.Domain.Tests/
├── SkillSwap.Application.Tests/      # тесты сервисов и валидаторов
└── SkillSwap.Api.IntegrationTests/   # Testcontainers (PostgreSQL + Redis)
```

- **Сервисы вместо CQRS:** контроллер вызывает метод сервиса из слоя Application (например, `ExchangeService.AcceptRequestAsync`). Сервис проверяет данные (FluentValidation), права, вызывает методы доменных сущностей и сохраняет изменения. MediatR не используется.
- **Транзакции:** один вызов сервиса = один `SaveChangesAsync`; где нужна блокировка (расписание, лимиты), сервис явно открывает транзакцию через `IUnitOfWork`.
- **Ошибки:** доменные исключения и ошибки валидации превращаются в ProblemDetails в одном глобальном обработчике (`IExceptionHandler`).
- **Идемпотентность webhook:** каждое событие LiveKit сначала записывается в `LiveKitWebhookEvents` с уникальным `EventId`. Повторная доставка падает на уникальном индексе и игнорируется (ответ 200). Из событий собираются интервалы присутствия в `SessionAttendances`.
- **Фоновые задачи (Hangfire, хранение в PostgreSQL):** напоминания, проверка урока на 15-й минуте и при закрытии комнаты, истечение заявок и слотов, завершение обменов по сроку, публикация отзывов, таймер 48 ч для обращений, закрытие кейсов через 7 дней, очистка чатов через 90 дней, выгрузка данных. Каждая задача идемпотентна: перед действием проверяет текущий статус.
- **Redis:** кэш каталога навыков, счётчики rate limiting, backplane SignalR.

### 11.2 Frontend (простая структура)

Фронтенд делается без сложных методологий: обычные папки по типу файлов и несколько проверенных библиотек. Этого достаточно для MVP и понятно одному разработчику.

## 15. Критерии приёмки

Модуль принят, когда проходят автотесты и ручная проверка по чек-листу.

- [ ] **Доступ:** без подтверждённого email отправка заявок → 403; после 5 неверных паролей вход блокируется на 15 минут; служебный аккаунт не входит без кода 2FA; заблокированный пользователь теряет доступ не позже чем через 15 минут.
- [ ] **Языки:** tg/ru/en переключаются без перезагрузки; ESLint без ошибок.
- [ ] **Подбор и лимиты:** без анкеты — редирект на онбординг; полные матчи выше частичных; 6-я исходящая заявка и 4-й обмен отклоняются.
- [ ] **Гонки:** два параллельных запроса на пересекающиеся слоты или на принятие заявок сверх лимита — проходит только один (интеграционный тест).
- [ ] **Часовые пояса:** сессия на 18:00 по Душанбе (UTC+5) видна партнёру в Москве (UTC+3) как 16:00; неотвеченный слот становится `Expired` в момент начала.
- [ ] **Видео:** совместно ≥ 30 минут → `Completed`; опоздание > 15 минут → `NoShow`, но если потом провели ≥ 30 минут → `Completed`; повторная доставка одного webhook не создаёт дублей; звонок идёт через TURN на 443 при заблокированном UDP; вне окна сессии `join-token` → 403.
- [ ] **Отзывы и модерация:** отзыв скрыт до второго отзыва или 7 дней; при взятии кейса оба участника получают ровно одно уведомление; после решения запрос чата модератором → 403; модератор не может взять кейс с участием своего личного аккаунта.
- [ ] **Роли:** админ получает 403 при попытке пригласить админа или изменить свою роль; админ может снять модератора; последнего суперадмина нельзя удалить или заблокировать; записи `AuditLogs` нельзя изменить ни через API, ни прямым запросом приложения к БД.
- [ ] **Данные:** в дампе БД текст сообщений зашифрован; восстановление из бэкапа на чистый сервер сохраняет читаемость чатов; выгрузка данных приходит на email.
- [ ] **16–17 лет:** при включённой настройке несовершеннолетний не видит взрослых в подборе и наоборот; жалоба из звонка сразу замораживает обмен.

## 16. Этапы, риски и решения

### 16.2 Риски

| Риск | Что делаем |
| --- | --- |
| Мало матчей на старте | 3 категории, частичные матчи, запуск через университеты и IT-сообщества |
| Провайдеры или сети блокируют WebRTC | TURN на 443/TLS, проверка на этапе 2, запасной план — LiveKit Cloud без изменения кода |
| Плохой таджикский перевод | Вычитка `tg.json` носителем языка до пилота |
| Перегрузка модераторов | Автофиксация неявок, история правок, приоритеты очереди |
| Потеря ключей шифрования | Ключи и сертификат в бэкапе, ежемесячный тест восстановления |
| Слишком сложная архитектура для команды из двух человек | Без CQRS/MediatR и FSD: обычные сервисы на бэкенде и простые папки на фронтенде |
| Безопасность несовершеннолетних | Правила раздела 10.4, решение по возрасту до пилота |

### 16.3 Решения

**Решено**

- Регион: международный запуск; медиасервер ближе к основной аудитории, другие регионы — позже.
- Авторизация: ASP.NET Core Identity.
- Бэкенд без CQRS и MediatR — обычные сервисы; фронтенд без FSD и Zustand — простая структура папок.
- Категории на старте: IT, Иностранные языки, Дизайн; конкретные навыки заполняются в админке.
- Платные функции: после MVP, отдельными таблицами.

**Ещё открыто** (не мешает начать код)

- [ ] Возраст: оставить 16+ с защитой из 10.4 или поднять до 18+ на MVP. Нужно до пилота (этап 8).
- [ ] Бюджет на серверы в месяц (сайт + медиасервер). Нужен до этапа 2.
- [ ] Окончательное название и домен. Нужны до пилота; в коде пока SkillSwap.
- [ ] Языки кроме tg, ru, en при широком запуске.

### 16.4 Что изменено по сравнению с v2.1

- `SessionAttendances`: убран уникальный `LiveKitEventId`; события хранятся в новой таблице `LiveKitWebhookEvents`.
- Защита от гонок для расписания и лимитов: блокировка строк пользователей вместо одного `RowVersion`.
- Статусы сессии: добавлены Expired, перенос, NotCounted, проверка при закрытии комнаты и правило для опоздавшего.
- Заморозка обмена останавливает срок; модератор может завершить обмен из Active.
- Апелляция: новый статус AppealReview и отдельный grant для второго модератора; обращение можно отозвать.
- Авторизация на ASP.NET Core Identity; поля `Users` приведены в соответствие.
- Убраны CQRS и MediatR (сервисы в слое Application); фронтенд упрощён: без FSD, Zustand, автогенерации типов и обязательного UI-кита.
- API: уведомления и их хаб, календарь сессий, отклонение слота, принятие приглашения, снятие модератора админом, выгрузка данных, завершение сеансов, запросы на бан, разблокировка пользователя.
- Новые таблицы: `CaseEvidence`, `BanRequests`, `LiveKitWebhookEvents`, `DataProtectionKeys`.
- Ключи Data Protection: хранение и бэкап.
- Отзывы: при штатном завершении достаточно 1 сессии, 3+ дают отметку «Полный обмен». В v2.1 при недоборе сессий отзыв оставить было нельзя.
- Добавлен раздел 10.4 о защите пользователей 16–17 лет.
- Возвращён блок «Решено / Ещё открыто».
